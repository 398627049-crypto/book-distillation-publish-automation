# 批量模式：多书名排期与检查机制维护

适用：用户一次给出多个书名与各自发布日期（如 6 本，每日 09:00 发布）。

## 一、批量执行顺序

1. **先对所有书完成阶段一（版本核实）与阶段二（敏感筛查）**，一次性确认排期调整方案（若有敏感书需跳过/顺延/换书），再动手做内容。不要做一本问一次。
2. 排期确定后建立任务清单（TaskCreate），每本书一个全流程任务 + 一个"设置定时发布与检查机制"任务。
3. 逐本走阶段三至阶段六（封面→蒸馏→humanizer→正文），可并行搜索版本资料，但内容创作逐篇进行以对齐格式。
4. 最后统一设置定时发布 automation 与检查机制。

## 二、排期顺延规则

- 跳过敏感书时，其余书整体前移一天填补空档，末位日期空出。例：原 12-03~12-08 六本，跳过其中一本 → 其余为 12-03~12-07，12-08 空出。
- 更新所有任务描述中的发布日期，使其与最终排期一致。

## 三、定时发布 automation

- 每本一个一次性（scheduleType=once）任务，scheduledAt=`YYYY-MM-DDT09:00`，cwds=素材根目录。
- **prompt 必须自包含**（未来运行时看不到本次对话）：写明标题、正文/封面绝对路径、剪贴板脚本路径、幂等预检、发布后核验、写日志格式、Edge 登录前提、全部用绝对路径（cwds 可能被系统改写，不依赖相对路径）。
- 创建后用 Python 把 nextRunAt 时间戳转北京时间核对，确保日期时间正确（历史用 `datetime.fromtimestamp(ts/1000, tz=timezone(timedelta(hours=8)))`）。

## 四、核验日志排期表

在 `发布核验日志.md` 的排期对照表追加每行：

```
| 日期 | 书名 | 标题 | 正文文件 | 封面文件 |
```

批量时一次性追加全部行，与 automation 一一对应。

## 五、兜底任务排期表与有效期维护

两个独立 recurring automation（午间 10:30、晚间 18:00）的 prompt 内含"日期→书名"排期对照表：

1. 追加本次各书的排期行（含标题、正文文件名、封面文件名）。
2. 把"若今天不在表内"的边界日期改成新的末位日期（如"如 12-08 及以后"）。
3. 用 `validUntil` 把有效期延到最后一本发布日期当天（如 `2026-12-07T23:59`）。
4. 更新前先 view 读取现有 prompt，避免覆盖其他配置。

## 六、最终核对

- automation 列表：确认每个发布任务时间正确、无重复、无遗漏；兜底任务有效期覆盖整个排期。
- 素材：每本书应有 5 个文件——`书封原图.jpg` / `头条封面.png` / `高保真拆书笔记.md` / `高保真拆书笔记-润色版.md` / `头条正文.txt`。逐一核对存在性。
- 向用户说明：所有任务只是定时，未实际发布；Edge 需在每个发布日保持打开并登录；"审核中"属正常。
