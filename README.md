# 图书蒸馏及发布全流程自动化

> 技术标识（skill name）：`book-precision-studio` ｜ 中文名：**图书精度skill**
> 一个把「一本书」变成「一篇已定时、可核验、能直接使用的今日头条拆书笔记」的端到端 WorkBuddy 技能。

一句话概括：给出书名（可批量+指定发布日期），自动完成**版本核实 → 敏感筛查 → 封面匹配 → 内容蒸馏 → 去 AI 味 → 生成正文 → 定时发布 → 定时检索发布情况**，并带幂等防重复与兜底补发。

---

## 一、功能清单

| # | 功能 | 实现方式 |
|---|---|---|
| 1 | **图书封面匹配** | 共享文件夹 → 当当 → 淘宝 → **豆瓣纯书封兜底**；下载按书名命名；ViewImage 核对三问（书名/版本一致、纯书封无促销、无其他销售图混入）；低清图只增强不换图，生成 1024×1536 竖版封面 |
| 2 | **图书内容蒸馏** | 调用 `high-fidelity-book-distillation` 产出 18 节高保真拆书笔记，按检查清单自检（来源标注、不编页码引文、英文混入清零、版本辨析） |
| 3 | **发布对应账号** | 通过本地 Microsoft Edge（沿用已登录的头条号），用剪贴板方案上传封面 + 填入正文发布；发布后回「作品管理」核验 |
| 4 | **去掉 AI 写作词语** | 调用 `humanizer` 做语言层去 AI 味（清理破折号堆叠、拔高词、AI 高频词），严守保真红线：不动论点/概念/证据/来源/18 节结构；另存润色版 |
| 5 | **定时自动发布** | 设定一次性 automation 在指定日期 09:00 发布，prompt 自包含绝对路径与幂等 SOP；支持批量多书排期与顺延 |
| 6 | **定时检索发布情况** | 午间 + 晚间两个独立兜底任务，定时核验作品管理、发现未发成功则自动补发、失败写日志并告警 |

---

## 二、触发方式

在 WorkBuddy 对话里直接说出意图即可，例如：

- `发布《乡土中国》到头条，2026.12.2 早上九点`
- `《乌合之众》发布头条笔记`
- `把《认知觉醒》蒸馏后发头条`
- `图书精度`

批量：`发布《A》《B》《C》，分别排 12-03、12-04、12-05 早九点`

## 三、目录结构

```
book-precision-studio/
├── SKILL.md                          # 主流程：7 个阶段 + 交付标准 + 已知限制
├── references/                        # 各阶段详细规范
│   ├── version-verification.md        # 阶段一 版本核实与译者/版次纠错
│   ├── content-screening.md           # 阶段二 敏感内容筛查
│   ├── cover-sourcing.md              # 阶段三 封面来源与核对三问
│   ├── distillation-checklist.md      # 阶段四 蒸馏 + 检查清单
│   ├── humanizer-guide.md             # 阶段五 去 AI 味与保真红线
│   ├── body-and-tags.md               # 阶段六 正文转换与话题标签
│   ├── publish-flow.md                # 阶段七 Edge 发布 SOP
│   ├── check-mechanism.md             # 阶段七 幂等核验/兜底补发/日志
│   └── batch-scheduling.md            # 批量排期与顺延
└── scripts/                           # 已实测的辅助脚本
    ├── fetch_douban_cover.py          # 按 ISBN / subject ID 抓豆瓣纯书封
    ├── enhance_cover.py               # 书封增强 → 1024×1536 竖版
    ├── md_to_toutiao.py               # 拆书笔记 md → 头条正文 txt
    ├── cover_lint.py                  # 英文混入/书名/尺寸自检
    └── set_clipboard_image.py         # 图片写入 Windows 剪贴板（CF_DIB）
```

脚本均为 Python，仅依赖标准库 + Pillow + pywin32（Windows）。

## 四、安装

把整个 `book-precision-studio/` 目录放到 WorkBuddy 的用户级技能目录：

```
C:\Users\<你的用户名>\.workbuddy\skills\book-precision-studio\
```

重启 WorkBuddy（或刷新技能列表）后即可通过中文名「图书精度」或「书名+发布笔记」触发。

> 目录名必须保持 `book-precision-studio`（与 `SKILL.md` 里的 `name` 字段一致）。

## 五、首次使用配置（重要）

本仓库为公开版本，**示例中的本机路径、共享目录、账号名均为占位符**，首次使用请按实际环境替换：

| 占位符 | 出现位置 | 替换成 |
|---|---|---|
| `D:/book-notes/` | SKILL.md、body-and-tags.md、cover-sourcing.md、check-mechanism.md、fetch_douban_cover.py | 你本机存放素材的目录（正文 txt、封面 png、核验日志都放这里） |
| `//你的主机/共享目录/书封/` | SKILL.md、cover-sourcing.md | 你预先放书封的共享文件夹；没有就删掉这条，改用当当/淘宝/豆瓣 |
| `"你的头条号"` | publish-flow.md | 你实际登录的头条号名称（仅作识别提示，不影响功能） |
| `mp.toutiao.com` 账号登录 | 发布阶段 | 先在 Edge 里手动登录你的头条号，脚本不处理登录 |

依赖安装：

```bash
pip install pillow pywin32
```

另外两个被依赖的技能需自行安装：`high-fidelity-book-distillation`（蒸馏）、`humanizer`（去 AI 味）。

## 六、诚实边界

- **不保证绝对零失败**：发布依赖本地 Edge 开着且已登录、浏览器自动化不中断；头条没有个人发布 API。方案价值在于降低失败率 + 失败可自发现自补救 + 告警留痕。
- **定时 ≠ 立即发布**：定时发布是在设定时刻由任务执行，未到点不会发布；登录态需在使用当天确认。
- **发布后状态可能是「审核中」**：头条所有内容需过审才公开，任务以「作品管理」列表出现为成功判据，不以"点了按钮"判定。
- **敏感题材**：比较政治学等政治敏感书籍会先询问用户处理方式（跳过/换书/顺延），不自行撰写发布。
- **真实书封优先**：禁止用生成图或其他书图替代；低清图可增强修饰，但明显不可用时停下请用户提供高清图。
